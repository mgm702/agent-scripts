# MVP

**Build as little as possible.** The goal is to start delivering value to your community as fast as possible — not to build something beautiful, polished, or complete.

## When to Use

- The user is ready to build their first product
- They're struggling with scope and over-building
- They have a validated problem and need the smallest thing that delivers value

## The Three Stages

1. **Manual** — solve the problem by hand for each customer. You *are* the product: support, fulfillment, engineering. Write down every step.
2. **Processized** — document the manual work so anyone could do it. Your "magic piece of paper" means someone else can take over.
3. **Productized** — automate the proven process. *Now* you build software — only what you've already proven works manually.

## The Four Build Questions

1. Can I ship it in a weekend? If not, cut scope until you can.
2. Does it make customers' lives a little better? That's the bar.
3. Is a customer willing to pay for it? Profitable from day one.
4. Can I get feedback quickly?

## What to Build

Most apps are just **forms and lists** (CRUD). Your MVP should be no more complex.
- **One thing.** Your product does one thing at first.
- **No polish.** Craigslist has never been pretty.
- **Charge money.** There's a huge gap between free and $1 (the zero-price effect).
- **Don't build what you can assemble.** Reach for off-the-shelf and no-code building blocks before writing custom code — whatever gets to market fastest.

## What NOT to Build

- Features you think you'll need "someday"
- For scale — you don't have scale problems yet
- A mobile app when a website works
- Code when a spreadsheet works
- A hire when no-code tools work

## Essentials Checklist

- [ ] Name the business (two real words > made-up word; pass the "radio test")
- [ ] Buy a domain (~$10/year)
- [ ] Build a simple site and deploy it — hand off to the `devops-agent` skill for hosting and a phased launch
- [ ] Create social accounts (personal + business)
- [ ] Set up payments
- [ ] Create an email for customer communication

## Output

Help the user define:
1. The single thing the MVP does
2. The simplest implementation (manual, no-code, or minimal code)
3. What they can ship this weekend
4. Their initial price point
5. How they'll collect feedback

For a code-based MVP, hand off scope to the `plan-and-annotate` skill before building. Ship early and often — the goal is to get less wrong as quickly as possible.
